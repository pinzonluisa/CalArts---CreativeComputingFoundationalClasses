Coding Art Fundamentals sits at the intersection of computer science, digital graphics, and creative expression. The course is built for beginners and introduces foundational programming concepts through visual art, motion design, and interactive media.

Code is treated here as a creative medium, not strictly as an engineering tool. The course draws on a long history of creative coding environments, from early tools such as Lingo to foundational texts like Daniel Shiffman’s The Nature of Code, and uses that history to build a flexible way of thinking about programming, one that transfers to any language or environment a student picks up afterward.

All class code examples live in the class code repository. The course divides into two halves, moving from core programming logic to a more advanced, performance oriented creative toolkit.

Part 1: Foundations and Interactive Logic (p5.js)

The first half focuses on core programming logic, taught in p5.js, a JavaScript framework built for visual artists. Each project builds in immediate visual feedback while covering:

  • Core computational logic: variables, conditionals, loops, functions, arrays, and classes
  • Visual math and graphics: Cartesian coordinates, trigonometry, color theory (RGB, HSB, alpha), and basic transformations
  • Weekly coding sketches, used to build fluency with syntax and basic logic through repetition

Midterm Project. This is where the first half’s skills come together. Skills don’t build if a student only memorizes what’s on the screen or repeats what’s demonstrated in class. Here, each student creates their own challenge: developing a story, building something they personally resonate with, at any level. Working through that idea means running into real problems to solve, and that’s where the logical thinking built over the first six weeks actually gets applied. The goal is to create something, simple or not, that the student is proud of and enjoys, built in a way that requires solving their own problems to reach their own goal. See the Midterm Project page for the full assignment.

Part 2: Intro to Systems, Simulation, and C++ (openFrameworks)

The second half moves into openFrameworks, a compiled, strongly typed C++ environment, based on the first two chapters of Daniel Shiffman’s The Nature of Code (natureofcode.com):

  • Introduction to Perlin noise and vector math
  • Translating the semester’s programming concepts into a framework capable of handling heavier graphics, real time interactivity, and system level performance

See the Course Schedule page for the week-by-week breakdown of this half.

Final Project. The final project is done in groups, intentionally. Collaboration and co-creation are a core part of any art practice, and one of the things that keeps human made work different from anything a machine can produce on its own. Working in a group also builds skills every professional needs: communicating clearly, solving problems together, asking for help, and reaching decisions as a team. See the Final Project page for the full assignment.

Portfolio

A GitHub Pages link for each weekly sketch builds a public, web accessible portfolio of working code, not files on a hard drive. The final project adds a digital recording of the performance as part of that same portfolio.

Future Pathways

The logic and mathematical foundations built in this course carry directly into later specializations, including:

  • Game design and development
  • 3D modeling and procedural systems
  • Physical computing, interactive installations, and robotics
  • Data visualization and generative art

Learning Outcomes

By the end of this course, BFA students will be able to:

  • Write and debug programs in both JavaScript (p5.js) and C++ (openFrameworks), using variables, conditionals, loops, arrays, functions, and classes
  • Apply core creative coding techniques, including randomness, vector math, and noise, to build an original interactive visual sketch
  • Build and publish interactive visual work to the web, including a working project hosted with GitHub and GitHub Pages
  • Connect a program to at least one other piece of software, using a protocol such as OSC

MFA students, in addition, begin building toward:

  • Building original tools or techniques that go beyond what’s covered in class
  • Taking a leading technical role in a collaborative, cross disciplinary final project

Course Structure

  • Class length: 1 hour 50 minutes
  • Review of the previous class and questions
  • Live coded demonstration of new concepts, with examples from the class code repository
  • Space for questions and troubleshooting
  • A look at example pieces that can be done using those concepts: artistic references

Class Recordings

Every class is recorded, and the recording stays available afterward for students who want to revisit it.

Students are encouraged to understand the logic behind each class’s coding concept rather than just copying what’s on the screen. In the weekly assignment, students can watch the recording and pause at each section to copy the code as shown, then are encouraged to adjust it in any way to experiment and understand the concept more deeply.

Materials

Students need a laptop capable of running both the p5.js web editor, which works in any modern browser, and, from Week 8 onward, openFrameworks, which requires a Mac or Windows laptop able to compile C++ and run Xcode or Visual Studio. No computer lab is available this semester, so this must be a student’s own machine.

  • A modern web browser, for the p5.js web editor
  • VS Code
  • A GitHub account, used for weekly submissions from Week 2 on, via GitHub Pages
  • Xcode (Mac) or Visual Studio (Windows), required to compile C++ for openFrameworks
  • openFrameworks (free), installed from a pre-recorded walkthrough assigned as homework before Week 8

Canvas is used for all weekly assignment instructions. No textbook purchase is required. A pre-recorded walkthrough of how to submit through GitHub Pages lives in Canvas, linked from every assignment. See the Resources page for class links.

Submission Model

Each week’s assignment is submitted through GitHub, via Canvas, turning that week’s coding concepts into an original piece. The Midterm and Final projects are both presented in person; see their own pages for details.

Credit Load

This is a 3-credit course, following CalArts’ standard credit-hour policy: 45 hours of work per credit for BFA students, 60 hours per credit for Masters students. That comes to 135 total hours for BFA students and 180 for Masters students across the semester. In-class time adds up to about 25.7 hours over the semester. The rest is independent work: roughly 7.8 hours a week for BFA students, and roughly 11 hours a week for Masters students.

Grading

Weekly assignments: 50% Midterm project: 20% Final project: 30%

The weekly assignments category splits evenly across however many weekly assignments actually run that semester, not a fixed per-assignment percentage.
