Part 1

Reading: Nature of Code, Chapter 0 (Random)

Book: natureofcode.com/random. Perlin noise section directly: natureofcode.com/random/#a-smoother-approach-with-perlin-noise.

Section by section summary, in the order Shiffman covers them:

  • Random Walks. Introduces the random walk as a path built from a series of random steps, using a coin flip on a balance beam as the starting image.
  • The Random Walker Class. Builds a Walker class with a position and methods to draw and step, using random() and floor() to pick one of four directions.
  • A Traditional Random Walk (Example 0.1). A walker takes one step per frame and leaves a trail on a background that is never cleared.
  • A Random Number Distribution (Example 0.2). Counts random picks into bins and graphs them, showing that random() is uniform and evens out over a large sample.
  • Pseudorandom Numbers. Computer randomness comes from deterministic math, not true chance. The sequence only looks random.
  • Probability and Nonuniform Distributions. Uniform randomness is often not natural enough, so this section introduces weighting outcomes instead of treating every option equally.
  • A Walker That Tends to Move to the Right (Example 0.3). Gives the walker a 40 percent chance to move right and smaller chances for the other directions, demonstrating weighted probability in practice.
  • A Normal Distribution of Random Numbers. Covers the bell curve, where values cluster around a mean, using height as the example, and introduces randomGaussian().
  • Calculating Mean and Standard Deviation. Walks through the arithmetic behind the normal distribution: averaging, squaring deviations, and taking a square root.
  • A Gaussian Distribution (Example 0.4). Draws semi transparent circles at x positions pulled from a normal distribution centered on the canvas, so the overlap visibly clusters toward the middle.
  • A Custom Distribution of Random Numbers. Covers oversampling in a random walk, the Lévy flight as a fix using occasional large jumps, and the accept-reject method for shaping a custom probability curve.
  • An Accept-Reject Distribution (Example 0.5). Keeps a random value only if a second random number also qualifies it, which lets the acceptance rate follow a chosen curve.
  • A Smoother Approach with Perlin Noise. This is the core section. Perlin noise is a sequence of pseudorandom values where neighboring values stay close together, giving smooth, organic motion instead of jumps. Shiffman also covers its history, including its origin in the film Tron and its common use in procedural textures.
  • Noise Ranges. noise() returns values from 0 to 1, and its argument is a position in noise space, not a range to sample from. map() is what rescales the output to fit the canvas.
  • A Perlin Noise Walker (Example 0.6). A walker whose x and y come from two different offsets sampled from the same noise space. Starting the two offsets far apart keeps the axes from moving in lockstep.
  • Two-Dimensional Noise. Extends noise to two dimensions, where a value resembles its neighbors in every direction, producing cloud-like textures when mapped to grayscale.
  • Noise Detail. Covers noiseDetail(), which controls how many octaves shape the noise’s texture, giving finer or coarser looking results.
  • The Ecosystem Project. An open-ended project prompt: build a digital pond ecosystem, starting with a creature whose behavior comes from a random walk or noise, with personality in the movement before any visual polish.
Part 2

Noise vs Random

random() gives a fresh independent value every time you call it. Nothing connects one value to the next. noise() works differently: nearby inputs give nearby outputs, so as the input creeps forward each frame, the output drifts instead of jumping.

random()

A fresh value every frame. The dot jumps, the graph is jagged.

noise()

Each value grows out of the last. The dot drifts, the graph is smooth.

How Noise Is Built

Same random points every time. Squeeze a lot of them into view and the line looks jagged, like random. Stretch out to just a few and the smooth curve between them shows, that is noise.

Same Noise, Two Starting Points

One curve, two markers sitting far apart on it. The code starts x and y at numbers like 0 and 10000. Here the two are closer together so both fit on one graph.

Same curve, now scrolling by underneath them. The two dots stay the same distance apart the whole time, because their starting points never change.

The same two dots, now just showing where each one currently sits on the line. When they land close together the dots stack up, when they do not, they sit apart.

Part 3

p5.js Example: Perlin Noise Walker

Sketch: editor.p5js.org/natureofcode/sketches/qyNwGUy59

This is Shiffman’s own Example 0.6 from the reading above. The Walker class keeps two offsets, xoff and yoff, starting far apart in noise space. Each frame, both offsets move forward by a small, fixed amount, and each one is passed into its own call to noise(), then mapped onto the canvas width and height. Because the two offsets never catch up to each other, the x and y motion never look the same, even though both come from the exact same noise function.

Part 4

Our openFrameworks Examples

F26-NoiseP1-Prep: one walker, straight noise

walker.hpp / walker.cpp. This is the direct openFrameworks version of the book’s Example 0.6: one walker, ofNoise() mapped straight onto the window.

walker.hpp 
class walker{
public:
    walker();
    float tx;
    float ty;
    float x;
    float y;
    void step();
    void show();
};
walker.cpp 
walker::walker(){
    ofSetCircleResolution(50);
    tx = 0.0;
    ty = 10000.0;
}

void walker::step(){
    x = ofMap(ofNoise(tx), 0.0, 1.0, 0.0, ofGetWidth());
    y = ofMap(ofNoise(ty), 0.0, 1.0, 0.0, ofGetHeight());
    tx += 0.01;
    ty += 0.01;
}

void walker::show(){
    ofFill();
    ofSetColor(100, 200, 10);
    ofDrawCircle(x, y, 20);
}

tx and ty start 10000 apart on purpose, for the same reason as the p5 example: two offsets that far apart on the same noise curve behave like two unrelated values.

F26-NoiseP2-Prep: many movers, noise as a steering force

mover.hpp / mover.cpp. Here noise is not the position itself, it is the force that steers the position, using ofSignedNoise() instead of ofNoise().

mover.cpp 
mover::mover() {
    r = floor(ofRandom(200,255));
    g = floor(ofRandom(0,200));
    b = 0;
    a = floor(ofRandom(20,50));

    x = ofGetWidth()/2;
    y = ofGetHeight()/2;

    radius = ofRandom(0.1,2);

    nPos1 = ofRandom(-1000,1000);
    nPos2 = ofRandom(2000,4000);

    n1Speed = ofRandom(0.001,0.005);
    n2Speed = ofRandom(0.001,0.005);

    xDir = 0;
    yDir = 0;

    maxSpeed = ofRandom(1,2);
}

void mover::display(){
    ofFill();
    ofSetColor(r,g,b,a);
    ofDrawCircle(x,y,radius);
}

void mover::update(){
    // the noise value becomes the steering force instead of a fixed direction
    xDir = ofSignedNoise(nPos1 += n1Speed);
    yDir = ofSignedNoise(nPos2 += n2Speed);

    xDir = ofMap(xDir, -1.0, 1.0, -maxSpeed, maxSpeed);
    yDir = ofMap(yDir, -1.0, 1.0, -maxSpeed, maxSpeed);

    x += xDir;
    y += yDir;
}

All 30 movers start at the center and drift outward because xDir/yDir are signed, so they can push in either direction, and get added onto position every frame instead of replacing it.

ofNoise() vs ofSignedNoise()

  • ofNoise(): returns a value from 0.0 to 1.0. Has overloads from one to four float coordinates, plus glm vector versions.
  • ofSignedNoise(): returns a value from -1.0 to 1.0. Same overloads, same inputs, only the output range differs.

In practice: ofNoise() fits naturally when the result maps straight onto a position, like walker.cpp above, because 0 to 1 is easy to stretch across a window with ofMap(). ofSignedNoise() fits naturally when the result is a force or offset added onto something that already exists, like mover.cpp’s xDir/yDir, since it needs to be able to push in either direction, not just one.

Part 5

Double Buffering and ofFbo

The graphics card keeps two full copies of the picture. One is on screen right now, the front buffer. The other is hidden, the back buffer, and that is where the next frame gets drawn. Once it is ready, the two swap, so what you see is always a finished frame, never one caught mid-draw.

with double buffering

Both copies stay ready with the same position. Whichever is marked front feeds the result below, and swapping between them never skips a beat.

without double buffering

There is only one copy, and the screen reads from it while it is still being redrawn. Part of what you see is the old frame, part is already the new one.

ofFbo: Drawing That Sticks Around

Up to now, every example clears and redraws the whole window each frame. ofFbo is for the opposite case: a buffer you draw into once, and whatever you draw stays there across frames until something draws over it again. That is what makes a trail, a painting surface, or anything else that should accumulate over time possible, instead of resetting to a blank frame 60 times a second.

minimal shape of it 
// setup()
fbo.allocate(ofGetWidth(), ofGetHeight(), GL_RGBA);
fbo.begin();
ofClear(0, 0, 0, 255);   // paint the starting background once
fbo.end();

// draw()
fbo.begin();
// draw here, it stays until you draw over it again
fbo.end();
fbo.draw(0, 0);           // show the accumulated result

    ofFill();

    ofDrawRectangle(0, 0, fbo.getWidth(), fbo.getHeight()); // new background is this rectangle
